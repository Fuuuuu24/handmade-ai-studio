## 2. 产品是什么

面向缺少拍摄条件的独立手作饰品商家，做一个「AI 助手带着走」的电商主图工作台：

- v0.6：商家上传正面、侧面、背面照片并确认三视图，和 AI 助手「小间」共创背景（或直接套用模板库里的背景图），小间写提示词，商家批准后用背景图＋三视图生成两张候选主图，再分「还原度」「风格」两项验收。
- 小间是核心，流程步骤只是次要的顶栏进度。小间能代用户操作，但生成只能用户亲自点、要确认的事先问用户、删除要用户在确认框里点、花钱有上限；这些硬规则由代码保证，模型不能绕过。
- 首版目标：约 5 位商家远程试用，看试用结束时是否愿意拿生成的图去发布（≥3 人继续）。

### 4.1 页面与外框

- 首页：输入框居中，上传照片、说一句话就开始（流程一）；下面是模板库的背景图（自己沉淀的在前、内置模板在后，最多 8 张），点「套用」开始流程二。
- 图标栏：作品、模板库、历史结果；底部「使用说明」，里面能导出试用记录。旧地址 `/style`、`/scenes` 跳到 `/templates`。图标栏悬停展开时盖在页面上；作品、模板库、历史结果的内容区左边留够了展开后的宽度（2026-11-23），不会被挡，工作区左边的对话仍会被盖住一点。
- 作品网格（封面用缩略图）。
- 模板库页（取代「我的风格」和「摄影布景」）：内置模板（现在是示意色块，标「示意，待替换」）和沉淀的背景图（参数、来源、沉淀时间、被几件作品用过）；套用、改名、删除（只做标记，已经选了它的作品照常可用）。
- 历史结果页：瀑布流（悬停看作品名、轮次、方案版本、比例、验收），点开大图，大图里可以「打开作品」到出图这一步。
- 出错页：页面或根布局出错时说明原因、可重试。本地数据库提示条：升级被别的页面挡住、或这个页面已经过时，提示刷新；升级后提示一次「旧的测试作品已清除」。
- 全局轻提示（右下角，可滑走）只用于成功告知；出错在原位置显示，不会自己消失。
- 图标按钮有悬停提示，键盘聚焦时也会出现。

### 4.2 工作区（左对话、右画布、顶栏细进度）

- 顶栏：作品名可改（小间也能直接改名）；状态、保存状态；按作品流程排的五步进度（完成打勾、失效打叉，小间回复或生成时当前步转圈）；删除作品。测试模式、服务未配置时标出；试用操作员模式显示预算余量。
- 商品：
  - 正面、侧面、背面三个上传位，另有细节照和未分类。首页和对话里传的照片先进未分类，用户或小间选类型；一个角度只放一张，被顶替的退回未分类（小间改时会弹确认框）。停用、替换都要确认，原图记录保留。
  - 三张都有才能「生成三视图」，每个角度一个任务。同角度的原图和三视图并排对照，逐张「可以用」（点错了能「取消确认」）；不像的单张重做（每张原图最多 3 次）。生成三视图时照片锁住。
- 信息：核心字段可标未知；小间写的只是建议，用户接受（或同意小间代点）后才生效，小间能撤回自己的建议；核心信息还有建议没处理时，这一步不算完成，批准处会提醒（不挡批准）；记下的后续需求（如真人佩戴）。
- 背景：二选一，「用模板库里的」或「自己生成」。
  - 自己生成：背景共创（共创记录、三项总结要用户确认或同意代点、「暂无明确故事」）→ 背景风格五项（来源标签；「你说的」下面显示核对过的用户原话；冲突提示）→ 背景方案和背景提示词 → 滑动批准并生成两张 → 选一张（提示「图里不能有饰品」）→ 可以起名沉淀进模板库。
  - 选定后背景风格只读，以背景图的参数为准；点「重新设计背景」才能再改、再生成。之后又改了总结、风格或品类尺寸时，提示「背景是按旧的内容生成的」。小间推荐风格之后总结又改了，提示风格可能要跟着变，可以「让小间按新总结调整」或「不用改」（AC-04.6）。
  - 套用模板进来的作品改成自己生成时，切到首页开始的流程（要确认），已有的照片、三视图和信息都保留。
- 摆放：摆放卡（摆放含展示用具、构图、合成禁止项）、合成比例（1:1／3:4／9:16）、合成方案（所用背景图和三视图小图、保真要求）；合成提示词能手改、核对、撤销、过期后确认仍适用，核心信息还有建议没处理时小间不写；缺项列表；滑动批准并生成两张（键盘按 End）。
- 出图：
  - 每轮两张独立任务。生成中显示扫光和状态；刚出来的结果从马赛克细化到清晰。部分失败可以补齐（每张最多补 2 次）。
  - 两项验收和问题标签、对照原图（可切换正面、侧面、背面、细节，原图和候选都能打开原尺寸）、这一轮的方案、从这一版修改（恢复那一版的摆放、背景图、比例、生图模型和提示词）。
  - 导出（两项满意才可，提醒发布时声明是 AI 生成）、「已经拿去发布了」、两版对比、验收含义说明。
- 商品、信息、背景、摆放四步底部有「下一步」：这一步做完才能点，不能点时写明缺什么；点了以后画布切到下一步，并排一个交接给小间。做完一步画布停在原处，等用户点「下一步」，或小间用 `next_step` 推进（不发交接）。

### 4.3 小间

- 真实对话、看图、流式回复、标注由哪个模型回复；模型返回思考过程时显示（想的时候展开，想完收起）。
- 失败时显示真实原因并可限次重试；超时首字 75 秒、整轮 150 秒；单轮最多连续 8 步。
- 27 个工具，清单见技术写法 13.7 和 14.8（2026-11-23 起没有能发起生成的工具；要用户确认的事用 `ask_confirm` 问、`confirm_for_user` 代点；删除类用 `request_delete` 弹确认框）。
- 对话里的卡片：批准（背景、合成两种）、方向选卡、生成三视图和补齐的提议、「要我替你点吗」、下载（附「这是 AI 生成的图」提醒）；系统代发的交接和通知显示成小卡片，不算用户原话。
- 跟上画布（技术写法 13.12）：「下一步」交接，三视图、背景、候选生成完成的通知，以及验收通知；排队、事务去重，等对话空闲、输入框里没字时才代发。小间按「我理解的现状 → 还没确认或有矛盾的地方 → 下一步」回话；作品状态里写明上次交接之后的变化。
- 输入框：「＋」上传照片、输入 `/` 出快捷命令（`/推荐`、`/暂无故事`）、对话模型和生图模型都能切换。
- 对话花费累加进作品累计花费。

- 开发和测试用的开关：假生图网关 `FAKE_GATEWAY=1`（按种类返回「TEST VIEW」「TEST BACKDROP」「TEST IMAGE」测试图）、假对话模型 `FAKE_CHAT=1`、试用操作员 `TRIAL_OPERATOR=1`（顶栏显示预算余量）。

### 4.5 硬规则（PRD 4.2 的 5 条全部由代码保证，都有测试）

1. 生成只能用户亲自点：三视图、背景、合成、补齐，小间只放卡片；批准和发起生成是同一下滑动；生成中按种类锁定。
2. 要用户确认的事（三视图、信息建议、标未知、共创总结、背景候选、沉淀、两项验收、流程二改自己生成）：用户在画布上点，或小间问过、用户同意后代点；代码核对问过之后用户的原话和东西没变（技术写法 14.4）。
3. 小间写商品信息只能是建议，共创总结只能是草稿，按第 2 条确认。
4. 总预算、单张上限、补齐次数（每张 2 次）、三视图次数（每张原图 3 次）都有上限。
5. 删除、停用、替换都要用户在确认框里点（小间可以发起）；原图不覆盖。

## 11. 已知限制与风险（代码里现有的行为）

- 生成等了 10 分钟没结果就判失败（`GENERATION.timeoutMs`）。如果网关之后才完成，钱已经扣了、结果拿不回来，补齐要再花一次。
- 对话调用失败或中止时，账本里预留的估价不退（宁可多记）；作品累计花费只算正常结束的对话。
- 删除作品会连同它的试用事件一起删，只留一条带花费的删除记录（试用记录里汇总成「已删除 N 件」一行）。
- 花费账本的锁只在一个进程里有效，部署时只能跑一个 Node 进程。
- 试用操作员开关是服务端环境变量，打开后所有访问者都看得到预算余量。
- 小间对风格卡的推荐直接写进风格卡、标「小间推荐」，批准方案即视为确认。这是开发时对 AC-05.1 的落实方式，没请发起人逐项确认。
- 三视图是生图模型重画的（v0.5 生图白底的初测里，常常没完整入框、改了结构），所以要商家逐张对照原图确认；合成只看三视图，三视图出错会被带进成品。
- 内置模板现在是示意色块：合成时把色块渲染成一张图当背景参考（界面标「示意，待替换」），合成效果不代表真实模板。
- 背景图里有没有饰品，代码判断不了，只能靠用户在选定和沉淀时把关。
- Seedream 的 `watermark: false` 经 AIHubMix 能不能生效，没验证。
- 开发时热更新会让对话面板拿到旧记录：现在保存会拒绝覆盖并提示刷新，生产环境没有这个问题。2026-11-01 开发中见过一次刷新后图片空白，之后重载 4 次都复现不了，疑似当时开发服务器正在重新编译。
- 价格是估价（`config/models.ts`），以 AIHubMix 后台为准。
- 「你说的」的原话核对只看片段在不在用户的原话里，不判断和这一项是否相关；旧作品的风格卡没有原话记录。
- 小间代点时，代码只核对同意的原话在问过之后出现过、东西没变，不判断那句话是不是同意的意思；小间理解错就会点错（卡片上写出引用的原话，三视图能取消确认，其余多数能在画布上改回）。真实对话模型的表现没测。
- 核心信息建议没处理时只提醒、不挡批准（发起人选定）：没接受的建议不进提示词，商家可能直接滑过提醒。
- 滑动批准只认真实指针（防误操作和脚本），自动化测试要走键盘（聚焦后按 End）。
- 刚生成的结果 20 秒内打开才播细化动画，之后直接显示。
- 轻提示 3.5 秒自动消失，只放成功告知；任何出错都在原位置显示。

## 12. 踩过的坑

- **React Bits 组件（2026-11-01 接入时遇到）**：
  - 上游代码有的在渲染时直接读 `window`，Next 预渲染会报错导致首页 500；改成服务端时按 0 算。
  - 组件自带的 `outline: none` 不在 Tailwind 的层里，会盖掉全局 `:focus-visible` 描边；每个组件要自己补焦点样式。
  - Prompt Bar 的输入框获得焦点时会关菜单；用键盘按「＋」或模型按钮时焦点从按钮移进输入框，菜单刚开就被关掉。要先移焦点再开菜单。
  - Masonry 的大图是挂在 `body` 上的，给组件外层加的样式管不到大图。
  - Refine Frame 的失败格子也是 `role="img"`，名字带「候选」；测试里找结果图要用 `/^候选 \d$/`。
  - Warm Tooltip 默认往上弹，放在顶栏的按钮要设 `side="bottom"`，否则跑到屏幕外。
- **v0.6 改造时遇到（2026-11-22）**：
  - 在 AI 代理里跑 `next dev`／`next build`／`npm run e2e`，Next 16.4.3 检测到代理（`AI_AGENT`、`CLAUDECODE` 等环境变量）会打出安全升级提示并让命令退出，下一次才放行，`next dev` 子进程重启时又会拦；跑之前 `env -u AI_AGENT -u CLAUDECODE -u CLAUDE_CODE`。
  - 不要手动删 `.next/dev/types`：开发服务器补生成这些类型文件时，页面会反复整页刷新一阵（tsconfig 包含这些文件）。
  - React 编译器的 lint 不许在 `useMemo` 里创建的回调中读写 ref；「根据上一次渲染调整状态」的写法（渲染时比较、调用 setState）可以用。
  - 以 `use` 开头的普通函数会被 lint 当成 React 钩子（作品操作 `useLibraryBackdrop` 因此改名 `chooseLibraryBackdrop`）。
  - chrome-devtools 连接超时两次（多半是 Chrome 的「允许」弹窗没人点），走查改用项目自带的 Playwright 起独立的无头浏览器。
- **修评审问题时发现（2026-11-23）**：
  - React Bits 组件自带的样式不在 Tailwind 的层里，除了盖掉焦点描边，也会盖掉全局的 `button:disabled`：Refine Frame 的「补齐这一张」禁用了却看不出来，要在组件样式里补 `:disabled`。
  - 本地的 `origin/main` 很久没 `fetch`，PR #9 早在 2026-11-07 合并了，文档却一直写「待评审」。接手时先 `git fetch origin`，用 `gh pr view` 看 PR 的实际状态。
- **写「小间的操作权限」时发现（2026-11-23）**：
  - AI SDK 7 的 `onToolCall` 在处理回复流的同一个任务里被等待：工具执行（包括等用户点确认框）期间状态一直是「回复中」。工具里不要 `await addToolOutput`（会互相等住），用 `void`。
  - `useChat` 的回调每次渲染都换成最新的（内部用 ref 转发），回调里读渲染时的值不会是旧的。
  - Playwright 里小间发起的确认框开着时，对话一直「回复中」，发消息的辅助函数不能等它回完（`say` 的 `settle: false`）。
- **代码评审时发现（2026-11-22）**：
  - 本地 `main` 很旧，`main...HEAD` 会把整个项目历史都算进来；评审或比较时用 `origin/main`，或者写明提交区间。
  - AI SDK 7 的 `sendMessage` 不防并发：`makeRequestImpl` 直接覆盖 `activeResponse`，连着调两次就会同时跑两条请求，回复交错写进对话。代发消息前要自己确认对话空闲。
  - `listTasks` 读出的任务不排序，任务编号又是随机 UUID，不能按数组顺序找「最后一次」，要按 `attempt` 排（`slotTasks`）。
  - 项目没有 React 组件测试库（只有 Vitest 加 `fake-indexeddb`），组件里的逻辑要抽成函数才能写单元测试。
- **框架太新**：Next.js 16、AI SDK 7 有破坏性变化（例如 `system` 改名 `instructions`、`onFinish` 改名 `onEnd`、`stepCountIs` 改名 `isStepCount`）。以 `正式代码/node_modules/next/dist/docs/` 和 `node_modules/ai/docs/` 的本地文档为准，不要凭记忆。
- **AIHubMix 生图接口**：
  - 必须开通异步任务，否则连同步调用也返回 403；同步调用不能带 `async` 字段。
  - 提交 `POST /ai/v1/images/generations` 带 `async: true`。
  - 轮询 `GET /ai/v1/images/{id}`，状态有 pending、in_progress、completed、failed、cancelled 五种。
  - 完成后带密钥下载 `output[].content_url`，约 1 小时过期、下载次数有限。
  - 各模型参数以 `https://aihubmix.com/call/schema/models/{模型}/endpoints` 为准：Gemini、Seedream 用比例，GPT、Qwen 用像素尺寸。Qwen 要关掉 `prompt_extend`，否则会改写提示词。
  - 按张计价的模型（Seedream、Qwen）价格在 aihubmix.com 的模型页上，公开模型接口里没有；Seedream 5.0 Pro 在网关上没有参数清单。
- **模型能力以实测为准**：`deepseek-v4-flash` 在模型目录里标了能看图，但带图请求返回 404，改用 `deepseek-v4-flash-vision-exp`。
- **模型表现**（3 条项链、30 张的初测，样本很小）：
  - Gemini 综合最好，但会自己补扣头和延长链。
  - GPT Image 2 对透明米珠还原最好，但常画成两端断开的 C 形。
  - Seedream 5.0 Lite 是国内模型里最有希望的，默认出 2048 像素，佩戴照没被真人规则拦截；它默认在图右下角加「AI生成」字样，提示词里写不要水印也没用，要传 `watermark: false`（第 5 节）。
  - Qwen Image 3.0 较弱。
- **提示词要写明**：整件饰品完整入框并留边距、保持闭合、不添加原图看不到的结构。生图模型出的白底常常不能完整入框，v0.6 的三视图提示词（`config/views.ts`）已经写明这一点，效果要等真实测试才知道。
- **AI SDK 7**：
  - 工具要声明 `outputSchema`，`addToolOutput` 的类型才对得上。
  - 流式响应用 `createUIMessageStreamResponse` 加 `toUIMessageStream`，`result.toUIMessageStreamResponse` 已废弃。
  - `useChat` 在组件卸载时会调用 `chat.stop()` 中止进行中的请求。
- **Next 16 开启了 cacheComponents**：
  - 读浏览器数据的页面要包 `<Suspense>` 并调用 `use(browser())`。
  - `useParams`、`usePathname` 在动态路由上会挂起，不包 Suspense 构建会失败（图标栏的导航已单独包好）。
  - 类型检查前要先跑 `next typegen`（`npm run typecheck` 已包含）。
- **开发模式（React 严格模式）会把组件「挂载→卸载→再挂载」演练一遍**：挂载时就发请求的副作用会被演练卸载中止，首页带过去的第一条消息因此丢过。要么推迟到下一轮（`setTimeout`，清理时取消），要么让副作用可以安全重复。
- **React 写法**：
  - `useEffect(() => 注册函数(...))` 如果注册函数有返回值，会被当成清理函数调用，要写成带花括号的函数体。
  - 对话面板每次挂载都要从数据库现读记录，内容变了才保存，否则会用旧记录覆盖数据库。
  - lint 不允许在副作用里同步设置状态、不允许在渲染时改 ref。编辑框用 `components/ui/draft-field.tsx`，本地图片显示用 `client/blob-urls.ts`。
  - 改一条记录的部分字段时，不要把渲染时拿到的整条旧记录写回去（会覆盖并发的修改），用 Dexie 的 `modify`（`repo.patchResult`）。
  - 弹窗内容早已挂载，React 的 `autoFocus` 在弹窗打开时不生效；用 `data-autofocus`，`Modal` 打开后会聚焦它。
- **Next 开发服务器里，不同接口可能各自加载同一个模块**：模块级变量（内存里的任务表、串行锁）不共享，热更新后也会重置。要放在 `globalThis` 上，假网关的任务表、账本锁已这样做。
- **`next/og` 的 `ImageResponse`（Satori）**：有多个子节点的 `div` 必须写 `display: flex`，否则渲染到一半出错，浏览器只看到连接中断。先 `arrayBuffer()` 渲染完再返回，错误才能如实报出来。
- **开发模式热更新会让对话面板重新挂载**：正在进行的对话会中断，改浏览器端代码前先等小间说完。
- **浏览器自动化**：
  - 用 chrome-devtools 连发起人的日常 Chrome 时，Chrome 每次都会弹窗请发起人点「允许」远程调试，没点就会超时。
  - 只开自己的隔离标签页（`isolatedContext`），用完关掉。
  - 截图和要上传的测试照片放系统临时目录（`$TMPDIR`），放 `/tmp` 会被拒绝。
  - `fill` 往长文本框里填字有时不会触发失焦保存；可以先点击、再 `type_text`、再按 Tab。
  - 测导出时拦截下载（替换 `HTMLAnchorElement.prototype.click`），别往发起人的「下载」文件夹里写文件。
  - 在发起人账户里新建凭据、替发起人同意协议，会被 Claude Code 的权限规则拦截，必须由发起人本人操作或明确再授权。
- **Playwright（2026-11-01）**：
  - 没下载 Playwright 自带浏览器，配置里用 `channel: 'chrome'`（本机和 GitHub 的 ubuntu runner 都有 Chrome）。
  - `npm run build` 会清掉开发编译缓存，之后第一次跑全流程时页面首次编译会刷新页面、打断测试；`tests/e2e/warmup.ts` 先把各页面请求一遍。
  - 名字匹配默认是包含：「用这张」会同时匹配「不再使用这张照片」，要加 `exact: true`。
  - Next 会把切走的页面藏起来留在 DOM 里，`getByText` 可能匹配到藏起来的元素；用 `getByRole`（默认跳过隐藏元素）。
  - 本地数据库写完才更新的勾选框，不要用 `check()`（它马上检查状态），先 `click()` 再 `expect(...).toBeChecked()`。
- **AI SDK 7 的测试模型**：`ai/test` 的 `MockLanguageModelV4`，`doStream` 返回 `simulateReadableStream`；工具调用块是 `{ type: 'tool-call', toolCallId, toolName, input: JSON 字符串 }`，结束块的 `finishReason` 是 `{ unified, raw }`。`streamText` 的超时参数是 `timeout: { totalMs, firstChunkMs }`。
