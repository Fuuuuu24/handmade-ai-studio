## 2. 产品是什么

面向缺少拍摄条件的独立手作饰品商家，做一个「AI 助手带着走」的电商主图工作台：

- 商家上传真实商品照片，和 AI 助手「小间」对话，共创作品故事与风格，小间写出提示词，商家批准后生成两张候选主图，再分「还原度」「风格」两项验收。
- 小间是核心，流程步骤只是次要的顶栏进度。批准生成、改长期风格、花钱上限这些硬规则由代码保证，模型不能绕过。
- 首版目标：约 5 位商家远程试用，看试用结束时是否愿意拿生成的图去发布（≥3 人继续）。

## 4. 写完了什么

都已在本地提交，并经单元测试、Playwright 全流程或 Chrome 走查验证过。逐条对照 PRD 见 [开发对照表第 9 节](development-map.md)。

**页面与外框**

- 首页：上传一张照片加一句话开始；4 套布景模版，点一张新建作品并预设布景。
- 图标栏：导航、使用说明、导出试用记录。
- 作品网格（封面用缩略图）、摄影布景页（内置模版、自己存的布景、版本历史、删除、「用这套开始」）、我的风格页（长期偏好和修改记录）、历史结果页（缩略图，点图打开出图）。
- 出错页：页面或根布局出错时说明原因、可重试。

**工作区**（左对话、右画布、顶栏细进度）

- 顶栏：作品名可改、状态、保存状态、五步进度、删除作品。测试模式、服务未配置时标出；试用操作员模式显示预算余量。
- 资产：多图上传、类型、停用、替换（都要确认，原图记录保留）。A 路线时可以生图白底，和原图并排对照后选用，没选用不能确认资产。试用操作员可以切 A／B 路线。
- 信息：核心字段可标未知；小间写的只是建议，接受后才生效；记下的后续需求（如真人佩戴）。
- 共创：共创记录、三项总结，只能由用户确认；「暂无明确故事」。
- 方案：布景（内置、自己存的、套用我的风格）、风格卡、冲突提示、比例、可读方案（含保真要求）、提示词（手改、核对、撤销、过期后确认仍适用）、缺项列表、批准并生成；存为布景（新建或出新版本）、更新为我的风格（勾选几项、看修改前后、同意才写）。
- 出图：每轮两张独立任务、真实状态、部分失败补齐（每张最多 2 次）；两项验收和问题标签、对照原图、这一轮的方案、从这一版修改；导出（两项满意才可）、「已经拿去发布了」、两版对比、验收含义说明。

**小间**

- 真实对话、看图、流式回复、思考过程、标注由哪个模型回复。
- 失败时显示真实原因并可限次重试；超时首字 75 秒、整轮 150 秒；单轮最多连续 8 步。
- 全部工具已接（22 个，清单见技术写法第 6 节；2026-11-01 新增 `suggest_name` 起名建议）。
- 对话里的卡片：批准、方向选卡、下载、存布景提议、我的风格提议。
- 对话花费累加进作品累计花费。
- 对话模型和生图模型都可以在输入框里切换。

**服务端**

- AIHubMix 对话与生图（异步任务、取回重试）。
- 花费账本：总预算、单张上限，内容被拦截时退回。
- 开发和测试用的开关：假生图网关 `FAKE_GATEWAY=1`、假对话模型 `FAKE_CHAT=1`、试用操作员 `TRIAL_OPERATOR=1`。

**硬规则**（PRD 4.2 的 5 条全部由代码保证，都有测试）

1. 批准只来自界面按钮；没有有效批准不能生成；生成中锁定方案。
2. 存布景、改我的风格只在用户点按钮时写入，小间只能提议。
3. 小间写商品信息只能是建议，共创总结只能是草稿。
4. 总预算、单张上限、补齐次数、白底次数都有上限。
5. 删除、停用、替换都要确认；原图不覆盖。

**健壮性**

- 打开任何页面都接着查询没完成的生成任务，不重复提交。
- 两个标签页同时轮询时，结果按任务去重。
- 参考图一律重新编码（按照片方向摆正）。
- 本地图片读不出来时，在图片位置说明原因。
- 对话保存时，拒绝用更短的旧记录覆盖已存的对话。

**试用记录**：「使用说明」→「导出试用记录」，下载 CSV。按 PRD 6.2 模板，能自动算的列已填，观察者要填的列留空。用匿名编号，不含作品名、照片和聊天原文。

## 9. 阿里云抠图方案（白底做法②，备用，暂不接）

> 2026-11-01 发起人指示「抠图模型先不接，之后定」。以下方案保留备用；如果改用别的服务，要重新调研。

完整方案见 [技术写法第 7 节「白底图的两种做法」](tech-design.md)。要点：

**为什么是它**：AIHubMix 没有抠图模型；发起人在「开源模型跑在自己服务器上／阿里云商品分割／fal.ai／先只做①」中选了阿里云（2026-11-01）。专为电商商品设计，国内服务，大陆正式版也能继续用。

**接口事实**（官方文档，2026-11-01 核实）：

- `SegmentCommodity`，API 版本 2019-12-30，地址 `imageseg.cn-shanghai.aliyuncs.com`；Node.js SDK 包 `@alicloud/imageseg20191230`（配 `@alicloud/openapi-client`、`@alicloud/tea-util`），本地文件用 `segmentCommodityAdvance` 直接传文件流。
- 默认返回带透明通道的 PNG；`ReturnForm` 还可以选 `mask`、`whiteBK`（白底）、`crop`。
- 图片：JPEG／PNG／BMP，不超过 3 MB，分辨率小于 2000×2000。
- 结果地址 **30 分钟内有效**，要立刻下载。
- 0.002 元／次（每月 1 万次以内，5 QPS），调用失败不收费，没有列出免费额度，欠费 24 小时冻结调用。

**发起人要做的**：

1. 注册阿里云（中国站，需实名）。
2. 在视觉智能开放平台开通「分割抠图」。
3. 建 RAM 用户，授权 `AliyunVIAPIFullAccess`，创建 AccessKey。
4. 自己把两行密钥写进 `正式代码/.env.local`（不要发在对话里）。
5. 少量充值（10 元约 5000 次）。

**代码怎么写**（详见技术写法第 7 节）：

- 新增 `config/matting.ts`、`server/aliyun-matting.ts`、`app/api/matting/route.ts`；浏览器端函数放 `client/generation.ts` 旁边（做法①的 `makeWhiteByGeneration` 在那里）。
- 服务端调阿里云、立刻下载 PNG、记账（失败退回）；浏览器把原图压到长边 1990 的 JPEG 再发，拿回透明 PNG 后铺纯白底，存成 `method: 'matting'` 的白底图。
- 资产页的白底面板（`components/canvas/asset-step.tsx` 的 `WhitePanel`）加一个「抠图白底」按钮，和已有的「生图白底」并列；对照、选用、确认的界面已经有了。
- 小间的 `make_white_asset` 加一个 `method` 参数（现在只有生图白底）。
- 没配密钥时界面如实显示「抠图服务未配置」；假网关模式下不调阿里云。

**实现时再核实**：控制台开通步骤和首购资源包；SDK 能否被 Next.js 正常打包（不行就加进 `serverExternalPackages`）；香港到上海的耗时；图片会经阿里云临时存储，试用前告知用户。

## 11. 已知限制与风险（代码里现有的行为）

- 生成等了 10 分钟没结果就判失败（`GENERATION.timeoutMs`）。如果网关之后才完成，钱已经扣了、结果拿不回来，补齐要再花一次。
- 对话调用失败或中止时，账本里预留的估价不退（宁可多记）；作品累计花费只算正常结束的对话。
- 删除作品会连同它的试用事件一起删，只留一条带花费的删除记录（试用记录里汇总成「已删除 N 件」一行）。
- 花费账本的锁只在一个进程里有效，部署时只能跑一个 Node 进程。
- 试用操作员开关是服务端环境变量，打开后所有访问者都看得到路线开关和预算余量。
- 小间对风格卡的推荐直接写进风格卡、标「小间推荐」，批准方案即视为确认。这是开发时对 AC-05.1 的落实方式，没请发起人逐项确认。
- 生图白底会重画像素（初测常常没完整入框、改了结构），所以要商家对照原图后才能选用。
- 开发时热更新会让对话面板拿到旧记录：现在保存会拒绝覆盖并提示刷新，生产环境没有这个问题。2026-11-01 开发中见过一次刷新后图片空白，之后重载 4 次都复现不了，疑似当时开发服务器正在重新编译。
- 价格是估价（`config/models.ts`），以 AIHubMix 后台为准。

## 12. 踩过的坑

- **框架太新**：Next.js 16、AI SDK 7 有破坏性变化（例如 `system` 改名 `instructions`、`onFinish` 改名 `onEnd`、`stepCountIs` 改名 `isStepCount`）。以 `正式代码/node_modules/next/dist/docs/` 和 `node_modules/ai/docs/` 的本地文档为准，不要凭记忆。
- **中文目录名**：npm 不接受中文包名，脚手架要在临时目录以英文名生成后再移入。
- **依赖版本**：Vitest 5 要求 `@types/node` 为 22 或 24 以上。
- **AIHubMix 生图接口**：
  - 必须开通异步任务，否则连同步调用也返回 403；同步调用不能带 `async` 字段。
  - 提交 `POST /ai/v1/images/generations` 带 `async: true`。
  - 轮询 `GET /ai/v1/images/{id}`，状态有 pending、in_progress、completed、failed、cancelled 五种。
  - 完成后带密钥下载 `output[].content_url`，约 1 小时过期、下载次数有限。
  - 各模型参数以 `https://aihubmix.com/call/schema/models/{模型}/endpoints` 为准：Gemini、Seedream 用比例，GPT、Qwen 用像素尺寸。Qwen 要关掉 `prompt_extend`，否则会改写提示词。
  - 按张计价的模型（Seedream、Qwen）价格在 aihubmix.com 的模型页上，公开模型接口里没有；Seedream 5.0 Pro 在网关上没有参数清单。
- **模型能力以实测为准**：`deepseek-v4-flash` 在模型目录里标了能看图，但带图请求返回 404，改用 `deepseek-v4-flash-vision-exp`。
- **模型表现**（3 条项链、30 张的初测，样本很小）：
  - Gemini 综合最好，但会自己补扣头和延长链。
  - GPT Image 2 对透明米珠还原最好，但常画成两端断开的 C 形。
  - Seedream 5.0 Lite 是国内模型里最有希望的，默认出 2048 像素，佩戴照没被真人规则拦截；它默认在图右下角加「AI生成」字样，提示词里写不要水印也没用。
  - Qwen Image 3.0 较弱。
- **提示词要写明**：整件饰品完整入框并留边距、保持闭合、不添加原图看不到的结构。生图模型出的白底常常不能完整入框，所以做法②要实测对比。
- **AI SDK 7**：
  - 工具要声明 `outputSchema`，`addToolOutput` 的类型才对得上。
  - 流式响应用 `createUIMessageStreamResponse` 加 `toUIMessageStream`，`result.toUIMessageStreamResponse` 已废弃。
  - `useChat` 在组件卸载时会调用 `chat.stop()` 中止进行中的请求。
- **Next 16 开启了 cacheComponents**：
  - 读浏览器数据的页面要包 `<Suspense>` 并调用 `use(browser())`。
  - `useParams`、`usePathname` 在动态路由上会挂起，不包 Suspense 构建会失败（图标栏的导航已单独包好）。
  - 类型检查前要先跑 `next typegen`（`npm run typecheck` 已包含）。
- **开发模式（React 严格模式）会把组件「挂载→卸载→再挂载」演练一遍**：挂载时就发请求的副作用会被演练卸载中止，首页带过去的第一条消息因此丢过。要么推迟到下一轮（`setTimeout`，清理时取消），要么让副作用可以安全重复。
- **React 写法**：
  - `useEffect(() => 注册函数(...))` 如果注册函数有返回值，会被当成清理函数调用，要写成带花括号的函数体。
  - 对话面板每次挂载都要从数据库现读记录，内容变了才保存，否则会用旧记录覆盖数据库。
  - lint 不允许在副作用里同步设置状态、不允许在渲染时改 ref。编辑框用 `components/ui/draft-field.tsx`，本地图片显示用 `client/blob-urls.ts`。
  - 改一条记录的部分字段时，不要把渲染时拿到的整条旧记录写回去（会覆盖并发的修改），用 Dexie 的 `modify`（`repo.patchResult`）。
  - 弹窗内容早已挂载，React 的 `autoFocus` 在弹窗打开时不生效；用 `data-autofocus`，`Modal` 打开后会聚焦它。
- **Next 开发服务器里，不同接口可能各自加载同一个模块**：模块级变量（内存里的任务表、串行锁）不共享，热更新后也会重置。要放在 `globalThis` 上，假网关的任务表、账本锁已这样做。
- **`next/og` 的 `ImageResponse`（Satori）**：有多个子节点的 `div` 必须写 `display: flex`，否则渲染到一半出错，浏览器只看到连接中断。先 `arrayBuffer()` 渲染完再返回，错误才能如实报出来。
- **开发模式热更新会让对话面板重新挂载**：正在进行的对话会中断，改浏览器端代码前先等小间说完。
- **浏览器自动化**：
  - 用 chrome-devtools 连发起人的日常 Chrome 时，Chrome 每次都会弹窗请发起人点「允许」远程调试，没点就会超时。
  - 只开自己的隔离标签页（`isolatedContext`），用完关掉。
  - 截图和要上传的测试照片放系统临时目录（`$TMPDIR`），放 `/tmp` 会被拒绝。
  - `fill` 往长文本框里填字有时不会触发失焦保存；可以先点击、再 `type_text`、再按 Tab。
  - 测导出时拦截下载（替换 `HTMLAnchorElement.prototype.click`），别往发起人的「下载」文件夹里写文件。
  - 在发起人账户里新建凭据、替发起人同意协议，会被 Claude Code 的权限规则拦截，必须由发起人本人操作或明确再授权。
- **本机网络很慢**（TLS 握手 18—35 秒，疑似代理）：这是网络问题，不是代码问题。
- **Playwright（2026-11-01）**：
  - 没下载 Playwright 自带浏览器，配置里用 `channel: 'chrome'`（本机和 GitHub 的 ubuntu runner 都有 Chrome）。
  - `npm run build` 会清掉开发编译缓存，之后第一次跑全流程时页面首次编译会刷新页面、打断测试；`tests/e2e/warmup.ts` 先把各页面请求一遍。
  - 名字匹配默认是包含：「用这张」会同时匹配「不再使用这张照片」，要加 `exact: true`。
  - Next 会把切走的页面藏起来留在 DOM 里，`getByText` 可能匹配到藏起来的元素；用 `getByRole`（默认跳过隐藏元素）。
  - 本地数据库写完才更新的勾选框，不要用 `check()`（它马上检查状态），先 `click()` 再 `expect(...).toBeChecked()`。
- **AI SDK 7 的测试模型**：`ai/test` 的 `MockLanguageModelV4`，`doStream` 返回 `simulateReadableStream`；工具调用块是 `{ type: 'tool-call', toolCallId, toolName, input: JSON 字符串 }`，结束块的 `finishReason` 是 `{ unified, raw }`。`streamText` 的超时参数是 `timeout: { totalMs, firstChunkMs }`。
