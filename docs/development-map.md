## 4. 硬规则落点（PRD 4.2，2026-10-31 已确认）

| 规则 | 代码里怎么保证 | 原型参考 |
| --- | --- | --- |
| 1 生成只在有效批准时执行；批准只能来自用户界面操作 | 批准记录只能由界面按钮创建，小间的工具没有「批准」；浏览器里的规则层在提交前校验批准有效（快照与当前方案一致）。服务端不存作品、不校验批准，只管预算（技术写法第 2 节） | v2 `generateBlockers`、`snapshotOf` |
| 2 改长期风格、已存布景需用户同意 | 小间只能创建「提议」，写入接口只接受用户确认的请求 | v2 长期风格确认更新 |
| 3 推测只能是待确认建议，不编造 | 小间写信息和总结的工具只能写「建议」状态；转成已确认需用户操作 | v2 待确认建议 |
| 4 成本计入，单次、重试、总预算上限写在配置里 | 服务端统一记账；超过上限拒绝调用并告诉用户；配置文件不进前端 | 无（原型无成本） |
| 5 删除、替换原图需确认；原图保留 | 删除和替换走确认弹窗；原图记录不可覆盖 | v3 `askConfirm`、`replacePhoto` |

## 5. 原型里不带进正式代码的部分

- 演示剧本（v3 `SCRIPTED`、`botSay` 固定回复）、示例总结和示例信息。
- 关键词规则：v2 `interpretChat`、`STORY_STYLE_RULES`、`AVOID_STYLE_RULES`，v3 `FIX_RULES`。它们只作为「模型应该能理解这些说法」的测试用例来源，不当作模型失败时的替代回复。
- canvas 合成的候选图和假白底（`makeCandidate`、`makeWhite`）。
- v2「演示设置」里的「模拟一张失败」：改为开发环境的测试开关。
- 原型可沿用的：视觉规范（v2 第三次改版的取色、字号、尺寸）、快照／差异／批准失效／冲突检测这类确定性规则、各状态的文案。
