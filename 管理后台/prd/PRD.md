# 一间管理后台 PRD

版本：v1.1，2026-11-01。v1.0 范围由用户确认：先交互原型，再独立管理版本；允许从主产品单向同步，禁止写回主产品。v1.1 由用户确认新增「供应商与凭据」：在后台统一管理 AIHubMix key，加密写进服务器上的凭据文件，由主产品读取；后台与主产品同机部署在香港服务器，经 SSH 隧道使用。

## 目标与边界

给项目维护者直观查看和整理小间的系统提示词、白底提示词和模型列表。在一个独立本地网站里完成修改、留版本和导出，避免直接翻源码。参考 CBI Admin 的侧栏、内容预览、列表筛选与详情编辑，不搬入账号运营、采购和商业化等无关功能。

提示词和模型的后台编辑仍只影响后台：主产品不读这些配置，“默认模型”“启用”都明确是后台配置。例外只有凭据（v1.1）：「供应商与凭据」页保存的 AIHubMix key 和团队口令写进服务器上的凭据文件，主产品从这个文件取 key。后台仍不调模型、不测试连通性、不写主产品源码与配置、不产生模型费用；key 只写不读回。部署到服务器需另行授权。

## 目录与阶段

- `prd/`：需求、技术方案、验收记录。
- `原型/`：可独立运行的交互原型，使用主产品真实配置的静态快照，修改保存在原型浏览器本地。同步只演示交互，不能伪称实时读取。
- `正式代码/`：独立本地网站，真实只读同步主产品文件；后台配置保存在该目录自己的数据文件。

执行顺序：PRD 与技术写法 → 完整交互原型 → 独立正式版本 → 功能与浏览器验证。每阶段报告，不重复询问已确认范围。正式版与原型都保留。v1.1 顺序：文档 → 原型加凭据页 → 主产品读取凭据 → 后台写入 → 协作者转发 → 本地验收 → 部署（主产品 `docs/tech-design.md` 第 12.10 节）。

## 页面

### 系统提示词

以“提示词列表 + 内容编辑器”为主，默认打开小间系统规则。提供搜索、原文/后台草稿切换、按 Markdown 标题跳转、字符数、来源文件、修改状态、保存及历史版本。保存前可查看差异；历史版本可恢复为新草稿版本，不覆盖历史。

固定项为小间系统规则与白底提示词模板。白底模板以 `{{keep}}` 展示可选保真要求，预览可输入该变量；小间提示词附加 `{{state}}` 展示请求时的作品状态，不编造真实商家数据。说明单件作品的最终场景生图提示词由小间动态生成，不属于固定系统提示词。

### 模型管理

搜索模型显示名/API ID，按对话/生图、启用状态筛选。表格展示厂商、用途、能力、后台状态、默认标记和来源状态。支持新增、编辑、启停和分别设置对话/生图默认模型。

对话模型字段：API ID、显示名、厂商、看图能力、推理强度、输入与输出价格（美元/百万 token）。生图字段：API ID、显示名、厂商、单张与单参考图价格、参考图上限、比例或尺寸策略、各比例尺寸、输出格式、额外参数 JSON。价格必须明确是估价。新增 ID 不得重复，不允许负价和非法参数。默认模型必须启用；必须先切换默认再停用该模型。原始配置只读。

### 供应商与凭据（v1.1）

首期只有 AIHubMix 一个供应商。「供应商」指发 key 的平台，页面和文档统一用这个叫法（用户 2026-11-01 定），和模型表里的「厂商」（模型出品方）不是一回事。之后可能增加别的供应商：模型出品方的官方接口，或别的中转（用户 2026-11-01）；到时要改的地方见主产品技术写法第 12.11 节。

- **排版**（用户 2026-11-01 定）：参考 CBI 后台「接入与采购」。分「模型凭据」「团队口令」两个标签；「模型凭据」表一行一个模型（主产品配置里的模型），第一列模型名、第二列供应商，后面是用途、Key 尾号、最近更新、状态和操作。同一供应商的模型共用一把 key：行内的替换、停用作用于这把 key，弹窗写明影响几个模型；上一把 key 的保留时间只在表格底部写一次。
- **状态**：未设置（服务器没配凭据文件位置或主密钥）、未配置、已配置（尾号、保存时间）、已停用、出错（读不出、格式不对、解密失败，写明原因，不自动清空或重置）。页面写明「已配置」只表示保存成功，不代表能调通。
- **配置与替换**：key 用密码框输入，保存后只显示尾号，任何接口都取不回原文。替换前要确认；换下来的 key 再保留 24 小时，只用来取回替换前提交的生图（AIHubMix 的生图任务按创建它的 key 隔离）。
- **停用与重新启用**：停用后主产品不再发起新的对话和生图，已提交的生图仍能取回；操作前要确认。页面提示：怀疑 key 泄露时，还要到 AIHubMix 后台停用或删除这把 key，这里的停用只管我们自己的服务。
- **团队口令**（协作者经服务器转发时用）：生成、更换、停用。生成或更换时只显示一次原文，之后只显示尾号。更换后旧口令立即失效，协作者进行中的生图会取不回，操作前要确认。
- **主产品当前读取**：显示主产品实际用的来源（环境变量、凭据文件或转发）、能不能用，以及它读到的文件版本和后台是否一致；主产品没运行或连不上时如实显示。
- **模型关联**：列出走这个供应商的模型（目前全部模型都走 AIHubMix），同一供应商不重复填 key。
- 不做连通性测试：测试要真实调用、会花钱，另行授权。
- 原型用演示数据，可切「演示状态」查看各种情况；输入的 key 只取尾号，不保存。
- 实现状态（2026-11-01）：原型、正式版和主产品读取都已实现，验证见 [验收记录](验收记录.md)「v1.1」；部署到服务器未做。

### 来源同步

展示允许读取的源文件、内容摘要和同步时间。用户先预览同步差异，再执行同步。源文件变化时更新只读基准；对未编辑项跟随源文件，对后台修改过的项保留草稿并标出分歧。主产品删除的项保留为“来源已移除”，新增项进入列表。重新同步不能静默覆盖后台草稿。后台默认模型单独维护，源默认变化仅在后台默认未改动时跟随。

### 修改记录与导出

按时间记录后台保存、模型变更、同步与版本恢复，以及凭据操作（时间、动作、尾号，不含原文和密文）。支持查看提示词版本、恢复成新版本，导出完整 JSON（含版本、来源和后台配置，不含任何凭据）。无发布入口；除凭据文件外不写回主产品。

## 验收标准

1. 默认数据来自手作工作台真实源码，首次载入有 2 个提示词、2 个对话模型、4 个生图模型；若源码后续变化，以真实同步结果为准。
2. 后台修改重启后保留；显示原始配置与后台配置差异。
3. 提示词草稿、版本恢复和模型新增/编辑/启停/默认设置可走通；非法数据返回具体错误，不能假保存。
4. 单向同步预览明确增删改，执行后保留冲突草稿。版本冲突拒绝保存并请用户刷新。
5. 浏览器可完成关键操作，支持键盘焦点、明确表单标签、空结果和失败反馈，提供截图证据。
6. 测试不调用真实模型、不用真实 key（用临时主密钥和假 key）、不改主产品源码；服务器只监听本机。
7. 保存后的 key 无法从任何接口、导出、记录、日志、后台数据文件或浏览器存储取回；凭据文件里只有密文、尾号和散列。
8. 主密钥缺失或错误、凭据文件损坏时明确报错，不清空、不重置、不回退到其他来源。
9. 替换后主产品的新请求用新 key；停用后主产品拒绝新请求，已提交的生图仍能取回；后台显示的文件版本与主产品读到的一致。
10. 凭据写入串行、带版本校验、原子替换，文件权限 600；版本冲突拒绝保存并请用户刷新。

## 已知限制

提示词和模型的后台配置不是主产品的生效配置（凭据除外）。没有账号：部署后靠 SSH 隧道把关，记录里不区分操作人；团队口令所有协作者共用一个，不能单独停某一个人。不做多供应商、自动轮换和更换主密钥的功能（更换主密钥后要在后台重新录入 key）。不管理用户作品及逐件生成提示词。源码结构不能被识别或导入失败时明确报错，禁止拿旧值冒充成功同步。
