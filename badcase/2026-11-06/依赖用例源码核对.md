# 依赖用例源码核对

核对日期：2026-11-06。范围：测试方案 v0.3 的 T02、T04、T06、T08、T09、T10、T11、T12。**仅源码核对，未执行真实链路，未调用模型、未花钱、未修改应用代码。** 下文的界面路径是将来获得付费测试授权后要执行的步骤，不是执行记录或通过结论。

## 结论与能力边界

1. **跨商品新建作品复用布景，当前只复用文字参数，不自动带旧结果作环境图。** `正式代码/src/domain/library.ts:11–25` 的布景只保存七项风格参数；`正式代码/src/client/create-work.ts:8–16` 只将 scene.id/params 交给 newWork；`正式代码/src/domain/work.ts:48–70` 新作品的商品信息、故事、提示词、批准重新开始。`正式代码/src/components/pages/scenes-page.tsx:118–125` 的「用这套开始」走这条路径。不存在该路径自动恢复某张房间基准图的证据。
2. **BC-006 追加环境图只服务“从某张结果修改”的这一轮。** `正式代码/src/components/canvas/output-step.tsx:117–120,212–222` 取本作品结果及其批准调用 reviseFrom；`正式代码/src/domain/work.ts:253–291` 记录 revision.fromResultId，再转为 approval.parentResultId；`正式代码/src/client/generation.ts:91–106` 在商品参考图后追加该结果图片。`startRound` 会清掉作品 revision（`work.ts:299–303`），该轮仍使用批准里保存的父结果 ID；以后直接重新批准不自动持续携带该图，要再次从指定结果修改。
3. **同一作品的结果分支与新商品档案是两条不同路径。** 从结果修改恢复风格、布景 ID、比例、生图模型、提示词，但保留当前商品信息、故事、照片（`work.ts:251–270`）。因此不能把旧作品停用照片、换成新商品的做法当作 T02/T04/T06/T08/T12 的“新作品”测试替代：这会遗留旧商品故事与档案，改变测试语义。
4. **源码证明了传参，不能证明空间一致性。** T09/T10/T11 有自动追加环境图的可执行路径；模型是否保留房间、正确换机位/商品位置，仍须真实结果验收。T02/T04/T06/T08/T12 可执行参数复用，但其视觉复用目标没有自动环境图支撑；不能把文字风格继承算作 R1/R2/R3 成功，也不能仅凭源码判生成必然失败。
5. 用例前置必须先通过。方案 `测试集/静态无字商品图/测试方案-v0.3.md:125–140` 规定依赖未达标记受阻；既有测试记录的受阻状态不能被本次源码核对解除。

## 共用执行路径与观察点

### 新作品路径（T02/T04/T06/T08/T12）

前置作品「方案 → 存为布景 → 命名/确认保存」；随后「摄影布景 → 对应已存布景 → 用这套开始 → 上传本例商品杂乱伪实拍 → 确认资产 → 补商品信息 → 共创并确认本件总结 → 方案 → 指定比例 → 让小间写提示词 → 审核 → 滑动批准并生成两张 → 出图验收」。开始布景会自动带入一条对话，真实模式下属于模型调用，**本次未点击执行**。

记录新旧作品 ID、布景版本、生成批准 ID、商品参考图与是否存在 parentResultId，避免只看到相同布景名称便误判带入房间图。新作品共创不能沿用旧作品确认状态。不要为补齐环境图，临时把旧生成图冒充整体/背面/细节商品照上传；这不是产品现有环境图复用入口，且会改变测试输入。

### 同商品结果修改路径（T09/T10/T11）

「作品 → 原前置作品 → 出图 → 明确指定前置最终候选 → 从这一版修改 → 方案 → 提交本例修改 → 小间核对/重写 → 审核 → 重新滑动批准 → 出图」。旧结果保留；新结果 parentId 来源于 task.parentResultId（`generation.ts:25–35,204–218`）。必要角度不足应补商品参考图或记受阻，不能允许模型凭空补背面。

“独立分支”可由每次重新点同一基准结果开始，但这不是复制一个隔离作品。商品事实、故事与上传照片会保留当前值；测试人员须核对期间没有改动它们。产品源码未提供本用例要求的独立作品克隆入口，不应声称已建立隔离副本。

## 修改、取消、比例与长期风格的专项边界

- **取消修改恢复范围有限。** `domain/work.ts:263–274` 保存/恢复的是 style、sceneId、ratio、imageModel、prompt；**不恢复商品信息、故事、照片、聊天，也不回滚已另行保存的布景/长期风格**。界面入口为 `plan-step.tsx:181–194` 的「取消修改」。若实验要恢复这些其他状态，应先记录并单独核对，不能把“取消修改”当整个作品撤销。
- **取消后不自动保留房间图。** revision 清掉后再批准，parentResultId 来自空 revision，会为 null（`work.ts:274,291`）。要沿用原候选图须重新从那张候选修改。
- **从新候选继续修改 vs 从原基准再开一支不同。** 前者取新候选图作环境依据，后者取原基准图。T09—T11 应记录准确父结果，避免把上一实验的空间变更带进下一实验。
- **改比例不裁切。** ratio 是依据和批准快照一部分（`domain/snapshot.ts:31–47,56–75`）；更改后提示词过期、旧批准失效（`domain/approval.ts:16–23,72–75`），新请求直接给模型所选 ratio（`generation.ts:100–106`）。代码没有证明模型按要求重新构图的最终质量，须看商品完整性与空间范围。
- **“从结果修改→只换比例→直接批准”不会必然重写提示词。** 过期时界面允许「我核对过，仍然适用」（`plan-step.tsx:155–159`），把依据更新（`work.ts:238–239`）。若提示词已有横版/旧比例描述，测试应明确让小间重写并检查冲突，不能将人工核对按钮当语义验证。
- **长期风格和布景只在用户保存时写入。** `client/library.ts:12–39` 是明确写入路径；普通 setStyle/applyScene/applyShopPrefs 只改 Work（`work.ts:164–193`）。但用户若在 T08 主动点击“更新布景/更新我的风格”并确认，改变就是已授权的写入，不属于局部覆盖自动污染。
- **照片上限会挡结果修改批准。** 自动环境图另占一个名额，商品照片已占满模型上限时要求停用一张（`domain/approval.ts:39–42`）。停用照片会影响素材确认，须重新确认；不能悄悄丢掉关键视角。场景参考图本身会按整体、背面、细节排序并截断到上限（`domain/snapshot.ts:7–25`），测试应记录实际提交参考图，不仅记录上传数量。

## 本次没有得出的结论

没有证明八条用例通过，也没有证明真实模型必然失败；没有修改测试通过条件。只确认：新作品布景复用与同作品结果修改采用不同的信息路径，只有后者自动追加旧结果图。后续若要求“换商品新档案也自动带房间图”，涉及布景/环境复用设计与数据模型，应由用户另行拍板，不在本次只读任务中实现。
