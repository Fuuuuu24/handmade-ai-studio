## 3. 首先处理的五项

### UX-01：布景新建入口返回后全部禁用（P1，实测缺陷）

复现：摄影布景→选已存布景“用这套开始”→进入作品→返回摄影布景。五个按钮均disabled；刷新后恢复。证据：[禁用状态](evidence/scenes-start-disabled-after-return.png)、[刷新恢复](evidence/scenes-start-restored-after-reload.png)。源码 `scenes-page.tsx:113,118–128` 在开始时设true，成功导航后没有恢复该状态；现象与此一致。

商家影响：给下一件商品继续拍时没有入口，不知道该刷新，以为系统仍在处理。建议将提交状态限制在这次创建操作，回到页面恢复可操作；保留防重复创建。验收必须覆盖“成功新建→回来→再建”，不能只测首建。属于产品缺陷修复，不需要重做产品方向。

### UX-02：方案审核重复、纠正事实后又过期（P1，实测＋源码）

T03用户纠正连接关系，小间同时写了信息建议与已修订提示词；用户接受建议后，提示词因商品信息变化被标过期。它明明已包含同一纠正，仍要再核对。方案页又同时展开风格编辑、可读方案和完整提示词；对非摄影商家，重复阅读太多。

建议默认只审核“这次照片＋可读摄影方案＋本轮改动＋批准”，完整提示词和细节编辑按需展开，符合已确认的“提示词可展开”方向；批量确认应逐项可审阅，不自动全接受。让“接受事实→确认方案”的顺序可见，避免助手先宣布可批准、用户接受事实后又失效。不能为省点击取消批准硬规则。

收益：把认真核对集中到一处，减少机械点接受。代价：需要检查工具续轮与版本关系；折叠不能把真实阻塞项藏起来。

### UX-03：原话标签仍不等于整项都来自原话（P1，实测）

T05明确说“奶油白墙、原木工作台、右侧窗、后方开放木架”，小间quote删掉“右侧窗”后逐字核对失败，降为推荐，还向用户解释系统原因。T01原话只包含“从桌前略高处斜拍”，构图却连“主体居中偏下、四周留边距”一起标“你说的”。证据：[T05整理](evidence/T05-info-story.txt)、[T01方案](evidence/T01-plan-r1.txt)。

现有检查有价值：找到不了原话会降级，确实执行了。它验证的是字符串出现，不能验证整项语义。建议保留真实原句，分开显示“你的要求”和“补充建议”；不要用一个命中片段给整段推断背书。误降级可由用户改正来源或保留原句，不让商家理解quote规则。收益是信任与纠正准确性；具体数据结构须另行设计确认。

### UX-04：同作品修改能参考房间，换商品却只有文字（P1，源码确认＋诊断实测）

两次修改提示词都明确写了“前1张商品、最后1张房间”，界面标明父结果，输出也明显保持原场景。**这一修复在本次样本有正向表现**。但T08新作品无旧结果图，布景保留的还是耳坠平放、耳钩侧放、树脂禁忌；将来换胸针，需要小间再识别并去掉这些残留。

建议先明确“保存摄影参数”和“继续使用这个房间”的不同能力，保存预览检查哪些是环境、哪些只适合当前商品；提供准确的继承说明。若要跨作品携带房间视觉依据，这是重要产品/数据设计，需另行拍板；不能把当前功能改个名字就声称做到。

收益：商家少重复描述，减少旧商品要求污染新商品。代价：房间图可能夹带旧商品误差、占参考名额，仍需真实性检查。本轮没有选定具体新增架构。

### UX-05：让商家负责精细验收，但对照工具不足（P1，实测＋源码）

对照弹窗已不裁下沿，T01实测完整显示，这是修复有效的部分。但 `output-step.tsx:54` 固定取第一张参考图，界面无细节/背面切换，也无局部放大。候选本身有大图链接，可独立看大图，**不是完全不能看大图**；不方便的是放大与原图的成对检查。

建议先做对照参考图切换、打开两侧原尺寸或独立缩放，再考虑同步拖动；生成前给出实际使用的商品图与房间图缩略图、各自用途。收益：上传细节图真正帮助验收，尤其细链、环、3个孔、透明边缘。代价：要补键盘操作和照片来源标识，不能只给鼠标手势。

## 4. 按钮与流程取舍

| 当前设置 | 判断 | 更好的处理及理由 |
|---|---|---|
| 滑动批准，键盘End，绑定版本 | 保留 | 防止无意花钱，硬规则有效；批准附近应显示参考缩略图、这次改哪项、预计费用。不要只写“已批准”的内部状态。 |
| 六项商品信息分别接受 | 安全但重复 | 用户原话已经清楚时可做一张可审阅的确认清单；仍允许单项修正/忽略。批量确认是建议，不能直接默认接受。 |
| 批准即生成两张 | 符合已确认方向 | 明确写“批准并生成两张”及本次总价，不再加一个没有信息增量的确认弹窗。是否允许只出一张会改变已确认范围，本轮不建议直接改。 |
| 改资料、比例后批准失效 | 保留 | 本轮手改、改比例都挡住了旧批准；要改善过期原因与变更对照，避免接受同一纠正后重复审核。 |
| “我已核对，两者一致” | 有用但依赖用户理解 | 本轮没用它替代T11的小间核对。可以保留人工恢复路径，展示冲突与改动，不暗示代码已做语义验证。 |
| 生成中不能改方案/模型 | 合理 | 保住本轮输入；可以允许写下“下一轮想改什么”的草稿，明确不影响当前任务，属于可选新增。 |
| 停止回复、超时重试 | 必要 | T07超时后工具结果保住；建议明示“信息/总结已保存，下一步写提示词”，避免用户以为整轮都失败。不要无脑重做工具。 |
| 从这一版修改 | 有价值 | 显示父图、参考用途及“尽量保持”，不要把“沿用房间机位”写成保证；本次保持成功但改动不足。 |
| 取消修改 | 含义需说清 | T07新增照片仍在且资产待确认。当前只还原方案相关字段，建议标明“取消本次方案修改，新增照片和聊天会保留”，不擅自删除照片。 |
| 两项满意才正式下载 | 符合现需求，但需讨论经营场景 | 商家可能想带走待修版本给别人看，不应被迫假点满意。可讨论单独“下载未验收稿”的出口及标识；不能直接改变现已确认规则。原尺寸取证走大图链接，不是正式验收导出。 |
| 加入对比 | 有用但反馈不够强 | T01点完后比较区插在上方，当前滚动位置没变，第一次截图仍看不到对比。建议自动滚到比较区或浮出“查看对比”，让操作结果可见。 |
| 用布景开始立即自动发聊天 | 可省一次开场，但有费用与等待 | 本轮新作品尚无照片就付费发“我想用这套布景”，模型又引导上传；可先展示确定性欢迎/上传提示，收到作品后再请求模型。无需取消完整Agent方向。 |

## 5. 目标用户还需要的细节（建议，不是本期新增承诺）

1. **知道这次到底带了哪些照片。** 区分商品整体/细节/背面与房间参考；满额时让用户知道要牺牲哪张、会影响什么。T07补图与保房间争抢4个名额，不能只说“再补图”。优先做选择与用途展示，不必先换模型。
2. **明确“保持什么、只改什么”。** 当前用户自然语言已经说得很清楚，提示词也写了，但输出几乎不改。需要前后改动复核与“改动没有生效”的反馈类别，别把成功出图当修改成功。ROI高于增加更多模板。
3. **关键商品细节检查表。** 将商家确认的9颗、3孔、非对称、透明等列在结果旁供人工查；不是AI自动保证。避免让商家只凭“漂亮”点像。
4. **真实等待预期与继续工作的指引。** 每张有状态，但“一两分钟”不是保证。建议显示已等待时长、能否离开、恢复方式、是否会重复计费；不要无依据造百分比。T05刷新恢复可作为已有能力说明。
5. **上传前的照片/数据提示。** 首次开始处说明照片会经AIHubMix送给模型、资料只存在当前浏览器；现提示藏在使用说明。补拍给具体例子，避免只说“拍清楚”。不新增强制摄影教程。
6. **完整作品备份/迁移。** 只导试用CSV不能带走作品图片、对话与版本。清浏览器或换电脑的风险对商家很实际；新备份能力涉及数据设计，应另行定范围。
7. **导出前的用途确认。** 像素、比例、格式、文件大小与“这是哪一版”对发布重要。O8已待定，本轮不编造平台规范，也不替用户选格式。可先展示原文件实际信息。
8. **成功后的下一件入口。** 结果下载、保存参数、继续拍下一件之间应有一条清楚路径；现在布景入口还会卡住。优先修顺这一条，不扩做批量、手机或真人佩戴。

## 6. 独立评审综合

设计针对性：作品语言、材料与不可改变细节、真实性/风格双验收贴合饰品商家；首页第一动作清楚。问题主要在审核和反复使用的成本，暂不需要换视觉风格或技术栈。

| Nielsen启发式 | /4 | 综合依据 |
|---|---:|---|
| 状态可见 | 3 | 保存、失效、单张状态明确；对比区和超时完成范围不够直观 |
| 贴近真实世界 | 2 | 资产、共创、提示词仍需商家翻译 |
| 控制与自由 | 3 | 版本、取消、停止存在；取消范围容易误解 |
| 一致性 | 2 | 布景返回按钮卡住；对话与手动编辑可能不同步 |
| 预防错误 | 3 | 未核对、比例变化、参考超限均挡住批准 |
| 识别优于记忆 | 2 | 审核表达重复；跨图细节对照不足 |
| 灵活与效率 | 2 | 双路径可编辑，但重复确认和无照片自动对话增加操作 |
| 简洁与审美 | 2 | 首页克制，方案页过密 |
| 错误恢复 | 3 | 超时有提示、工具保留、刷新恢复生成；布景按钮需刷新 |
| 帮助说明 | 2 | 有使用说明，缺关键时刻的任务内引导 |
