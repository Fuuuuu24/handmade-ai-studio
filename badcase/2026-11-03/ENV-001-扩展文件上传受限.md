# ENV-001：浏览器扩展自动上传受限

分类：工具／测试环境限制，不是产品缺陷。状态：已通过原生选择框绕开，未改设置、未修应用。

## 复现与现象

在 T01 首页先等待 filechooser，点击“上传照片”，调用选择器 setFiles 指向测试集原始 PNG。工具返回：需在 Chrome 扩展详情启用 “Allow access to file URLs”，`fileChooser.setFiles failed`。当时图片未进入产品预览。

## 原因与置信度

直接原因（高置信）：当前 Chrome 扩展缺少文件网址访问权限，工具在向网页传送文件前拒绝操作。依据是工具明确错误；没有证据说明产品文件 input 有错。

## 等价路径与结果

使用当前 Codex 原生 Chrome 应用控制：切到本轮测试标签 → 点击上传 → 系统文件框用“前往文件夹”定位同一 PNG → Open。网页出现预览、“移除这张照片”和可用的“开始”。证据见 [截图](evidence/T01-upload-ready.jpg)。

原生输入路径时 typeText 未正确保留中文；paste 后 AX 也未变化。最终使用原生 setValue 设置完整 Unicode 路径并 Return，路径和文件预览正确后才点 Open。该现象仅记录为操作工具限制，未进一步诊断系统输入机制。

## 影响

增加测试准备步骤，不影响成功上传后的输入文件。未修改扩展权限，未另装自动化工具，未把该问题计入模型／商品图验收失败。后续上传优先使用可用的原生文件选择框。
