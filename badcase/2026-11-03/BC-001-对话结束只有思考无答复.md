# BC-001：真实对话结束时只有思考，缺少正式答复和下一步

严重度：高，阻断 AI 主导流程。状态：未修复；已有一次人工提示后的恢复。用例 T01，作品 `work_b663503b24874bea`。

## 复现

1. 默认 Qwen 3.8 Flash、Seedream 5.0 Lite；只上传 T01 的杂乱图，发送自然开场。
2. 首次网络问题排除后补发继续请求。
3. Qwen 流持续约 150 秒，最终只有长篇英文思考，末尾 `But I shouldn't fabric`，没有中文正文或工具推进，界面从“停止回复”回到禁用的“发送”（输入为空）。无可见超时／空答复错误提示。
4. 从产品模型选择器切到 DeepSeek V4 Flash 看图实验版，发送“上一轮只有思考内容，没有答复……告诉我下一步”。同样结束后只有折叠思考，无正文。展开显示长篇推演，末尾句子不完整。

## 预期与影响

应给出下一步，或明确提示本轮未能完成及可恢复操作。当前让用户只能主动追问，且思考内容不能代替正式结果。模型连通成功不等于 Agent 流程可用。

## 证据

- [Qwen 截图](evidence/T01-reasoning-only.jpg)、[DOM 原文](evidence/T01-reasoning-only.txt)
- [DeepSeek 截图](evidence/T01-deepseek-reasoning-only.jpg)、[DOM 原文](evidence/T01-deepseek-reasoning-only.txt)
- 服务日志：Qwen 请求约 2.5min；DeepSeek 首轮约 12.7s。HTTP 200 不能代表有正文。

## 原因分析（分层，不冒充完整根因）

确认的运行表现：两种真实模型均出现 reasoning-only 结束，卡片未推进。Qwen 请求时长与产品 `totalMs=150000` 一致，疑似超时截断；没有保存原始 finishReason，不据此确认。

代码依据：`src/config/budget.ts` 的 maxOutputTokens 为 1500；`src/app/api/chat/route.ts` 同时传 reasoning 与 maxOutputTokens，错误处理只处理流错误，没有检测“结束但无正文且无工具结果”。`src/components/chat/chat-panel.tsx` 仅依赖 useChat 的 error 显示失败，ready 状态无空结果提示。

候选原因：①模型思考消耗输出额度，尚未写正文即到限；②Qwen 总时限截断，流未以可见 error 呈现；③网关兼容流结束／usage 行为异常。缺少原始 usage 与 finishReason，尚不能在三者间定根因。账本仍 reserved，也不能声称有完整结束元数据。

## 实际恢复（人工帮助，非原生无障碍通过）

再发一次“请不要输出分析过程，直接用两句中文告诉我现在要确认什么。潮汐间是店铺名，商品叫潮线项链”。DeepSeek 随后调用起名／品类建议并给出确认资产、补材料的中文答复。工具自动续轮，日志约 60s＋3.3s。手动接受名与品类、确认资产后才能继续。此恢复不能抹去前两次失败。
