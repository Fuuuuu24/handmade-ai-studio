# ENV-002：本地 Node 服务未启用环境代理，首轮对话连接超时

分类：运行环境阻塞。未修应用代码；用户指出并授权使用代理。

## 复现

T01 上传杂乱图，以自然开场点击“开始”。工作区出现照片和用户消息，小间一直思考，约 38 秒后提示：`Failed after 3 attempts ... Cannot connect to API: Connect Timeout Error`。服务端日志三次均为 `aihubmix.com:443` 连接超时（每次 10000ms），不是模型拒答或商品识别错误。

## 原因与证据

已确认本机系统代理 HTTP/HTTPS/SOCKS 均为 `127.0.0.1:10808`；进程环境已有 HTTP_PROXY、HTTPS_PROXY、NO_PROXY，但启动未设置 Node 的环境代理启用项。代码通过 AI SDK 默认网络调用，`src/server/aihubmix.ts:16` 未显式设置代理。用户指出代理原因后，只用 `NODE_USE_ENV_PROXY=1` 运行 Node 的无 key `/v1/models` 连通探测，返回 HTTP 200。随后以相同启用项重启本地 Next 服务。该对照支持未启用代理是首轮连接失败的原因（高置信）；真实对话是否成功尚需下一轮验证。

## 恢复步骤

停止本轮启动的开发服务 → `NODE_USE_ENV_PROXY=1 npm run dev -- --hostname 127.0.0.1` → 使用已有工作区继续。不修改 .env.local、系统代理、密钥或生产代码。

重启后“重试”按钮消失；自动点重试失败（找不到按钮），重新读取页面确认原图和原始消息仍在，以“刚才网络超时没有收到你的回复，请继续看我上传的照片和上一条需求。”补发恢复。该额外消息不算商家正常共创步骤。

## 证据限制

首轮错误已由实时 AX 状态和服务端日志确认；重启后才保存的 `T01-after-server-restart.*` 已是恢复页面，不能作为错误截图使用。错误文字以上述实时观察为准。后续错误应在重启前先保存证据。
