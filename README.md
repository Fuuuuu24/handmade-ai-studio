# 一间 · 手作影像工作台

理解手作故事，帮助独立手作商家制作真实、有个人风格的电商商品主图。

> **项目阶段：正式开发（M2）进行中。** 需求见 PRD v0.5；`原型-v3/`（对话为主）是已定稿的交互原型，助手、白底和候选图都是本地演示。`正式代码/` 按技术写法开发中：真实 AI 对话（小间）和真实生图已接入，业务功能和界面组件（React Bits）已写完（白底只有生图白底一种做法，抠图先不接）；**还没在真实饰品上测过模型效果和成本，也没有部署**。尚不能交给试用用户使用，进度见 [交接文档](docs/handoff.md)。

## 产品方向

- AI 助手「小间」是核心：用户用自己的话说需求，小间在对话中带着走完全流程，流程步骤只作为次要的进度显示；批准生成、改长期风格、花钱上限等硬规则由代码保证；最终提示词由小间撰写（PRD v0.5）。
- 作品列表与单件工作区，长期保存商品资产、共创记录、方案和结果版本。
- 先深入共创；用户不知道如何表达时，通过推荐选卡形成作品总结。
- 商品真实性与风格分别验收，两项均通过才算完成。
- 单件作品、多张参考图；静物展示优先，真人佩戴后续验证。
- 主图比例可选 `1:1`、`3:4`、`9:16`；每次一种比例、两张候选图；对话框里可切换对话模型和生图模型。
- 首版只做电脑浏览器；试用为远程试用。
- 审核摄影方案和提示词后生成，保留版本并支持对比。
- 保存并复用摄影布景，逐步积累店铺视觉风格。

以上为已确认需求，不代表全部已经实现。完整范围与待决策项见 [PRD](docs/PRD.md)。

## 本地运行

### 正式代码（开发中）

需要 Node.js 24。首页、作品、工作区（小间对话、真实生图、验收、从指定版本修改）、摄影布景、我的风格、历史结果都已可用；写完了什么、还没写什么见 [交接文档](docs/handoff.md) 第 4—6 节。

```sh
cd 正式代码
npm install
npm run dev                  # 真实调用模型（花钱，受预算上限约束）
FAKE_GATEWAY=1 npm run dev   # 生图走假网关：不花钱，图片是测试图（只在开发环境生效）
```

默认访问 `http://localhost:3000`。接入模型需要在 `正式代码/.env.local` 写入 `AIHUBMIX_API_KEY=...`，该文件不入库。

### 原型 v3（AI 对话为主，推荐查看）

`原型-v3/` 按 PRD v0.3 起的对话为主方向重做布局（正式界面照它做）：首页输入框居中、下方摄影布景模版；工作区左边和小间对话、右边画布展示当前步骤，五步缩成顶栏细进度；左侧图标栏、顶栏、作品／布景／历史结果页沿用 v2 的样式。无第三方依赖。

```sh
cd 原型-v3
npm start
```

默认访问 `http://127.0.0.1:4175`；也可以直接打开 `原型-v3/index.html`。点「用示例耳饰试一试」体验。**小间的回复是写好的演示剧本，未接大模型**：点对话卡片上的按钮推进，自由输入它读不懂；数据只在内存，刷新即清空。

## 验证与已知限制

`正式代码/` 下运行 `npm test`（149 个单元测试）、`npm run e2e`（4 条 Playwright 全流程，假对话模型＋假生图网关）、`npm run typecheck`、`npm run lint`、`npm run build`，2026-11-01 均通过；主流程在 Chrome 桌面宽度下也用真实对话模型实测过，并在 Chrome 里只用键盘走过一遍。没做 Safari 等其他浏览器、读屏与真实用户测试，生成效果和成本还没在真实饰品上系统测过。

`原型-v3/` 下运行 `npm run check` 检查脚本语法。v3 已在 Chrome 桌面宽度下实测示例路径与模版路径、批准失效、各页面和删除确认，未测真实照片上传、导出、窄屏，也未做跨浏览器、触屏与真实用户测试。

仓库的 `Source checks` 工作流检查旧 `原型/` 的服务脚本，并新增 `正式代码/` 的单元测试、类型检查、lint、构建和全流程测试（2026-11-01 加入，已在 GitHub 上跑通）；不覆盖 `原型-v3/`、`管理后台/`。通过不代表模型效果或真实性已验证。

## 如何一起维护

1. 提出问题或功能建议，请创建 Issue；报告问题时不要公开密钥、用户照片或私人聊天。
2. 准备改动时，Fork 仓库，在自己的分支上开发。
3. 阅读 `agents.md` 与 PRD，将 Pull Request 提交到本仓库 `main`。
4. 由仓库所有者审核并决定是否合并。提出 Issue 或 PR 不会自动获得仓库写入或合并权限。

首批真实用户试用由项目发起人协调。欢迎围绕工作台、需求流程、可访问性和真实图像能力提出建议。
