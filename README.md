# 一间 · 手作影像工作台

理解手作故事，帮助独立手作商家制作真实、有个人风格的电商商品主图。

> **项目阶段：产品需求评审（PRD v0.3）与本地交互原型。** `原型-v3/` 是 AI 对话为主的新布局（小间回复为固定演示剧本）；`原型-v2/` 是表单驱动、能完整走通五步的旧布局。两者的助手、白底和候选图都是本地演示，**尚未接入真实 AI 对话、白底处理与图像生成**。当前仓库不能作为完整生图产品使用。

## 产品方向

- AI 助手「小间」是核心：用户用自己的话说需求，小间在对话中带着走完全流程，流程步骤只作为次要的进度显示；批准生成、改长期风格、花钱上限等硬规则由代码保证（PRD v0.3）。
- 作品列表与单件工作区，长期保存商品资产、共创记录、方案和结果版本。
- 先深入共创；用户不知道如何表达时，通过推荐选卡形成作品总结。
- 商品真实性与风格分别验收，两项均通过才算完成。
- 单件作品、多张参考图；静物展示优先，真人佩戴后续验证。
- 主图比例可选 `1:1`、`3:4`、`9:16`；每次一种比例、两张候选图。
- 审核摄影方案和提示词后生成，保留版本并支持对比。
- 保存并复用摄影布景，逐步积累店铺视觉风格。

以上为已确认需求，不代表全部已经实现。完整范围与待决策项见 [PRD](docs/PRD.md)。

## 本地运行

原型位于 `原型/`，正式代码将放在 `正式代码/`（尚未开始）。需要 Node.js 18 或以上，当前没有第三方依赖，无需先运行 `npm install`。

```sh
cd 原型
npm start
```

默认访问 `http://127.0.0.1:4173`，仅监听本机回环地址。可通过 `PORT` 环境变量调整端口。

目前只能查看页面骨架：`index.html` 引用的 `app.js` 尚未实现，交互入口不会工作。样式含外部字体请求，离线时使用系统字体回退。

### 原型 v3（AI 对话为主，推荐查看）

`原型-v3/` 按 PRD v0.3 的方向重做布局：首页输入框居中、下方摄影布景模版；工作区左边和小间对话、右边画布展示当前步骤，五步缩成顶栏细进度；左侧图标栏、顶栏、作品／布景／历史结果页沿用 v2 的样式。无第三方依赖。

```sh
cd 原型-v3
npm start
```

默认访问 `http://127.0.0.1:4175`；也可以直接打开 `原型-v3/index.html`。点「用示例耳饰试一试」体验。**小间的回复是写好的演示剧本，未接大模型**：点对话卡片上的按钮推进，自由输入它读不懂；数据只在内存，刷新即清空。

### 原型 v2（表单驱动的完整流程）

`原型-v2/` 按 PRD v0.2 重做；视觉参考 Lovart（实测取值：小字号、细描边、克制配色，全无衬线），左侧为悬停展开的图标栏，作品名与操作在顶栏，目前只适配桌面宽度。无第三方依赖。

```sh
cd 原型-v2
npm start
```

默认访问 `http://127.0.0.1:4174`；也可以在 Chrome 中直接打开 `原型-v2/index.html`。首页可「载入示例作品」直接体验；数据只存在当前浏览器。演示内容（白底、候选图、助手回复）均有明确标注，不代表真实 AI 效果。

## 验证与已知限制

```sh
cd 原型
node --check server.mjs
npm run check
```

`原型-v3/` 下运行 `npm run check` 检查脚本语法；v3 已在 Chrome 桌面宽度下实测示例路径与模版路径、批准失效、各页面和删除确认，未测真实照片上传、导出、窄屏。

`原型-v2/` 下运行 `npm run check` 检查全部脚本语法。v2 已在 Chrome 桌面宽度（1440×900、1280×800）下实测主流程，此前还验证过服务访问限制和输入转义；未适配手机，也未做跨浏览器、触屏与真实用户测试。

旧 `原型/`：`node --check server.mjs` 可检查现有服务脚本语法。当前 `npm run check` 因缺少 `app.js` 不能通过；补齐脚本后应运行完整检查并验证浏览器流程。

仓库的 `Source checks` 工作流检查已有脚本语法，并在业务脚本缺失时明确提示；其通过不代表产品流程、模型效果或真实性已验证。

## 如何一起维护

1. 提出问题或功能建议，请创建 Issue；报告问题时不要公开密钥、用户照片或私人聊天。
2. 准备改动时，Fork 仓库，在自己的分支上开发。
3. 阅读 `agents.md` 与 PRD，将 Pull Request 提交到本仓库 `main`。
4. 由仓库所有者审核并决定是否合并。提出 Issue 或 PR 不会自动获得仓库写入或合并权限。

首批真实用户试用由项目发起人协调。欢迎围绕工作台、需求流程、可访问性和真实图像能力提出建议。
